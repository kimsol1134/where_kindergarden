**버전**: 1.2.0

**상태**: MVP 개발 중

## 1. Executive Summary

### 1.1 Product Vision

> "모든 부모가 5분 안에 주변 유치원을 발견하고, 데이터 기반으로 자녀에게 최적의 기관을 선택할 수 있게 한다."

### 1.2 Problem Statement

현재 유치원/어린이집 선택 과정에서 부모들이 겪는 핵심 문제:

| 문제 | 현재 상황 | 임팩트 |
|-----|---------|-------|
| **정보 분산** | 유치원 알리미, 각 기관 홈페이지, 맘카페 등 여러 소스에서 정보 수집 | 평균 2-3시간 소요 |
| **비교 어려움** | 정보 형식이 다르고, 동시 비교가 불가능 | 비효율적 의사결정 |
| **위치 기반 검색 부재** | 행정구역 기반 검색만 가능, 실제 거리 파악 어려움 | 통학 거리 오판 |
| **모바일 최적화 부족** | 공공 데이터 사이트의 낮은 모바일 사용성 | 이동 중 검색 불가 |

### 1.3 Solution

**GPS 기반 주변 유치원 자동 검색 + 원클릭 비교표 생성** 서비스

```
[현재 위치 or 주소 입력]
        ↓
[반경 내 유치원/어린이집 자동 수집]
        ↓
[거리순 정렬 + 필터링]
        ↓
[최대 3개 기관 비교표 생성]
        ↓
[카카오톡/링크 공유]
```

### 4.2 MVP Features (Phase 1)

| 속성 | 내용 |
|-----|-----|

### 5.3 Design Principles

| 원칙 | 설명 | 적용 예시 |
|-----|-----|---------|
| **Mobile First** | 모바일 경험 우선 설계 | 터치 최적화 (48px 터치 영역) |
| **Progressive Disclosure** | 필요할 때 정보 노출 | 상세 정보 인라인 확장 |
| **Data-Driven** | 수치 기반 비교 | 최적값 시각적 강조 |
| **Shareable** | 공유 가능한 모든 상태 | URL 기반 상태 관리 |
| **Minimal** | 미니멀 화이트 디자인 | 회색 계열 + 초록 액센트 |

## 7. Constraints & Assumptions

### 7.1 Constraints

| 유형 | 제약사항 | 영향 |
|-----|---------|-----|
| **기술** | Kakao Maps API 일일 호출 제한 | 클라이언트 캐싱 활용 |
| **비즈니스** | 유치원 알리미 API 키 운영 계정 필요 | JSON 갱신 시 사용 |
| **리소스** | 1인 개발 | MVP 범위 최소화 |
| **데이터** | JSON 파일 크기 (8.5MB) | gzip 압축으로 ~1.5MB, 초기 로딩 스켈레톤 |
| **데이터** | 데이터 신선도 | 학기별 갱신, 데이터 버전 UI 표시 |

### 7.2 Assumptions

| 가정 | 리스크 | 대응 |
|-----|-------|-----|
| 타겟 사용자의 70%가 모바일 사용 | 데스크톱 사용자 불편 | 반응형 디자인으로 대응 |
| 비교 기능이 핵심 가치 | 단순 검색만 원하는 사용자 | 목록에서도 충분한 정보 제공 |
| 공유 기능 활용도 높음 | 공유 없이 개인 사용 | 비교표 자체 가치 확보 |

## 8. Risks & Mitigations

| 리스크 | 발생 확률 | 영향도 | 대응 방안 |
|-------|---------|-------|---------|
| JSON 데이터 노후화 | 중간 | 낮음 | 학기별 정기 갱신, 데이터 버전 UI 표시 |
| 초기 JSON 로딩 지연 | 중간 | 중간 | 8.5MB 파일 gzip 압축, 로딩 스켈레톤 UI |
| Kakao API 호출 제한 초과 | 중간 | 중간 | 클라이언트 캐싱, Rate Limiting |
| 모바일 GPS 권한 거부 증가 | 중간 | 중간 | 주소 검색 대안 UI 강화 |
| 경쟁 서비스 출현 | 낮음 | 중간 | 비교표 UX 차별화 |
| 유치원 알리미 API 스펙 변경 | 낮음 | 중간 | JSON 갱신 스크립트에서만 영향, Transformer 분리 |
| 저사양 기기 성능 이슈 | 낮음 | 중간 | Web Worker 활용, 가상화 목록 적용 |
