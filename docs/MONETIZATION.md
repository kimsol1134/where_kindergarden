# 우리동네 유치원 — 수익화 계획 (Monetization Plan)

> 작성일: 2026-06-28
> 작성 관점: "세계 최고 앱 마케터"의 비판적 검토를 거친 최종안
> 현재 상태: 유저 ~100명, 일 2~3 다운로드(월 ~80), iOS 네이티브가 메인 앱

---

## 0. 한 줄 결론 (TL;DR)

**100명 단계에서 수익화는 시기상조다. 진짜 제약은 "수익"이 아니라 "성장·신뢰·계절성"이다.**
따라서 이 문서는 *"지금 돈 버는 법"*이 아니라 *"수익이 자연히 따라오게 만드는 단계별 계획 + 단계를 여는 임계치(gate)"*다.

- **지금(H1)**: 유료화 기능 만들지 말 것. 무료 성장 루프 + 광고(바닥 수익) + 의도 계측 + **모집철 집중**.
- **다음(H2)**: 트래픽 임계치 돌파 시 **B2B 노출 상품** 파일럿(우리가 만든 의도 데이터가 영업 무기).
- **나중(H3)**: 양면 마켓플레이스 + B2C 시즌패스(WTP 검증 후) + (재고려) 제휴.

---

## 1. 비판적 진단 — 왜 대부분의 "수익화 아이디어"가 지금은 틀렸나

### 1.1 수익 산수 (환상 제거)

| 레일 | 100명 가정 | 1,000명 가정 | 판정 |
|------|-----------|-------------|------|
| B2C 시즌패스 ₩3,900 (전환 10%, 연 1회) | ~₩39,000/년 | ~₩390,000/년 | 빌드 비용 대비 무의미 |
| AdMob 배너/네이티브 (저빈도) | 월 수천 원 | 월 수만 원 | 푼돈이지만 비용 0 → "바닥"으로 유지 |
| B2B 노출 상품 (원당 ₩50k/년) | 사실상 0 (팔 명분 없음) | 20곳 × ₩50k = ₩1M/년~ | **유일하게 실수익 잠재. 단 트래픽 게이트** |

> 핵심: **모든 B2C 유료화는 1,000명에서도 푼돈.** 유료화 기능에 쓰는 시간은 성장에 쓸 시간을 빼앗는다.

### 1.2 철회/수정하는 이전 아이디어

- **소셜 티커("지금 N명이 보고 있어요")** → ❌ **철회.** 100명에선 실제 숫자가 초라(주당 0~1명)해서, 거짓이면 신뢰 파괴·사실이면 빈약함 노출. 규모(H2+) 전엔 독.
- **유료 비교 리포트** → 🔁 **무료로 전환.** 무료 비교/공유가 이미 North Star인데 유료화하면 바이럴을 죽인다. 리포트는 **공유되는 성장 무기**로.
- **광고** → 🔁 **폐기 아님, "바닥 수익"으로 유지·최적화.** 전략은 아니지만 비용 0.
- **제휴(CPA)** → 사용자가 제외 결정. 존중. (이 버티컬·단계에서 ROI는 가장 높았음 — H3에서 재논의 여지만 남김.)

### 1.3 가장 큰 구조적 문제: 계절성 + 저빈도

- 앱이 유효한 기간 = **연 6~10주(모집철, 대략 10~12월 처음학교로 + 연중 어린이집 대기)**.
- 결과: **구독 모델 사망**(10개월 이탈). 시즌패스도 연 1회 좁은 창에서만 판매.
- 대응 2축:
  1. **연중 레일 확보** = 웹/SEO 에버그린 콘텐츠(아래 §5.3). 검색 의도를 연중 포획.
  2. **모집철 화력 집중**(§5) — 획득·바이럴·광고 인벤토리를 그 창에 몰빵.

---

## 2. 전략 원칙 (모든 결정의 기준)

1. **수익은 트래픽×신뢰의 함수다.** 신뢰가 먼저. 신뢰를 태우는 수익화는 음(陰)의 ROI.
2. **진짜 마감만이 정직한 긴박감이다.** 이 앱엔 *실제* 모집 마감이 있다 → 가짜 카운트다운·"N자리 남음" 절대 금지.
3. **데이터가 합리화 엔진이다.** 13개 API 객관 데이터(교사 근속·급식 직영·1인당 면적·CCTV·인증) = 맘카페 "카더라"를 이기는 해자.
4. **공유되는 무료 산출물 = 성장 엔진.** 가장 좋은 것을 무료로 풀어 바이럴 계수를 올린다. 수익은 그 뒤에서 회수.

---

## 3. 3-호라이즌 로드맵 (임계치 게이트)

각 단계는 **앞 단계 지표를 충족해야** 다음으로 넘어간다. 게이트 미달 시 머무른다.

### H1 — 지금 ~ (게이트: MAU < 1,000 또는 모집철 트래픽 스파이크 미검증)
**목표: 수익이 아니라 성장·신뢰·계측.**
- 무료 성장 루프 강화: 비교 → **브랜드 박힌 공유물** → 신규 유입(바이럴).
- 광고: 현 AdMob을 **바닥 수익**으로 유지하되 위치만 최적화(목록 네이티브 1개, 전면광고 금지).
- 의도 계측: ✅ 이미 완료(`Contact Tapped` 등). 이게 H2 게이트 판단 근거.
- 모집철 플레이북(§5) 1회 실행 → 데이터 수집.
- **하지 말 것: 유료화 기능 빌드.**

### H2 — MAU 1,000+ 또는 모집철에 특정 구(區)에서 의미 있는 트래픽 (게이트: 아래 §7 임계치)
- **B2B 노출 상품 파일럿** (핵심): 의도 데이터로 영업 — *"이번 달 학부모 N명이 귀 원을 봤고 M명이 전화했습니다."*
- **B2C 시즌패스 A/B**로 WTP만 검증(광고 제거 + 모집/마감 알림 묶음). 매출 기대 말고 **결제 전환율 학습**.

### H3 — MAU 10,000+ / 다지역 트래픽
- 양면 마켓플레이스(원장 셀프 등록·스폰서 노출).
- 시즌패스 정식화.
- (재고려) 제휴 — 사용자 재승인 전제.

## 4. 수익 레인 평가표

| 레인 | 적합도 | 난이도 | 수익 잠재력 | 핵심 리스크 | 언제 |
|------|:-----:|:-----:|:----------:|------------|------|
| **광고(AdMob)** | 중 | 낮음(완료) | 낮음 | 과다 노출 시 신뢰 훼손 | 지금(바닥) |
| **B2B 노출/리스팅** | 높음 | 높음(영업) | **높음** | 트래픽 게이트, 영업 조직 필요 | H2 |
| **B2C 시즌패스** | 낮음 | 중 | 낮음 | 계절성·저빈도·WTP 미검증 | H2(검증) |

## 5. 모집철 플레이북 — 실제로 돈·성장이 나오는 유일한 창

연 1회 좁은 창에 모든 것을 집중한다.

### 5.1 타이밍
- 처음학교로/유치원 모집 일정 역산 → **D-30부터 획득 캠페인, D-7~D-day가 사용·공유 피크**.

### 5.2 바이럴 (가장 중요)
- **공유물에 브랜드/딥링크 박기**: 부모가 배우자·조부모에게 비교표를 보내는 순간이 곧 신규 획득. 공유 카드 디자인·CTA를 이 시즌에 최적화.
- **무료 맞춤 비교 리포트**(공유 가능) = 바이럴 + (H2부터) 결제 유도 포인트.

### 5.3 연중 레일: 웹/SEO 에버그린 (계절성 방어)
- Next.js 웹 자산으로 *"OO구 유치원 고르는 법", "국공립 vs 사립 비교", 지역별 가이드* 콘텐츠.
- 연중 검색 유입 → 앱 설치 유도 + 디스플레이 광고. **오프시즌 생존 + 모집철 부스터.**

### 5.4 광고 인벤토리
- 피크 트래픽 동안만 네이티브 광고 노출 밀도 소폭 상향(신뢰 한계 내에서).

## 6. 설득 3원칙 — "파는 순간"에만, 정직 버전 (H2부터 적용)

> 원칙 자체는 강력하나, 신뢰 상품에 *문자 그대로* 쓰면 역효과. 반드시 아래로 **번역**한다.

### 6.1 결과를 그려준다 (스펙 ❌ → 미래 ✅)
- ❌ "13개 항목 비교 제공"
- ✅ *"원서 전날 밤, 검색창 7개 띄워놓고 불안해하는 대신 — 확신을 갖고 3곳을 정한 나."*
- ✅ *"마감을 놓쳐 1년을 더 기다리는 악몽을, 안 겪은 나."*

### 6.2 옆 사람이 사게 한다
- **얼굴/영상 후기**: 부모 프라이버시상 영상은 무리 → **실명 1~2개 앱 사용 후기**로 충분. 유치원 후기는 더 생생히 노출.
- **마감/카운트다운**: **진짜 모집 마감 D-day만.** 가짜 타이머 금지.
- **소셜 증거**: H1에선 보류(숫자 부족). **H2+에서 실제 수치만** 노출(예: "이번 달 강남구 학부모 N명이 비교").

### 6.3 명분을 제공한다 (감정으로 사고, 이성으로 합리화)
- 객관 데이터 + 공시 출처 + 후기 = *"맞아, 이건 맞아"*의 근거. 결제·선택의 정당화 레이어.

## 7. 측정 — 어떤 지표가 어떤 게이트를 여는가

이미 구축한 의도 이벤트(`Contact Tapped` / `Homepage Opened` / `Directions Opened` / `Review Opened`)가 판단 근거.

| 게이트 | 임계치(제안) | 근거 지표 |
|--------|------------|----------|
| H1 → H2 진입 | 모집철 MAU 1,000+ **또는** 단일 구에서 주간 `Contact Tapped` 의미치 발생 | Mixpanel MAU, `Contact Tapped` by `kindercode`/지역 |
| B2B 영업 개시 | 특정 유치원이 월 수십 회 조회 + 수 회 전화 유발 | `Detail Opened`·`Contact Tapped` per `kindercode` |
| B2C 시즌패스 검증 | 무료 사용자 중 알림/리포트 수요 신호(`Alert Requested`) | 수요 probe 탭률 |
| 바이럴 건전성 | 공유 1건당 신규 설치(K-factor) 추적 | `Compare Shared` ↔ 설치 코호트(ASC) |

> **현재 적용**: 모집철 알림 수요를 검증할 fake-door UI와 이벤트 계약(`Alert Requested`)을 추가했다. 실제 알림은 §8처럼 로컬 알림으로 백엔드 없이 구현 가능하다.

## 8. "빈자리/모집 알림" — 가능하다 (발상 전환)

실시간 데이터가 없을 뿐, **알림은 실시간일 필요도 백엔드가 필요할 필요도 없다.**

1. **모집 시즌/마감 알림 (가장 쉬움, 백엔드 0)** — 모집 일정은 매년 공지되는 캘린더. 기기 로컬 알림(`UNUserNotificationCenter`)으로 "관심 유치원 우선모집 D-3" 예약. **이게 앱의 "진짜 카운트다운"** = 원칙 6.2를 정직하게 쓰는 유일한 길.
2. **빈자리 변동 알림 (배치 diff, MVP는 클라이언트만)** — 이미 빈자리 데이터셋을 주기 갱신 중. 앱이 받는 데이터에서 "지난번 본 빈자리 vs 지금"을 비교 → "관심 유치원에 빈자리가 생겼어요(최신 공시 기준)" 인앱 배지. APNs·서버 불필요. *정직한 라벨이 곧 신뢰.*
3. **실시간 대기순번** — 데이터 없음. 포기.

> 알림의 1차 목적은 **수익이 아니라 리텐션**(저빈도·계절성을 깨는 재방문 훅). 유료화는 그 위에 H2에서 얹는다.

## 9. 지금 당장: Do / Don't

### ✅ Do (H1)
- 공유물에 브랜드/딥링크 박아 바이럴 계수 올리기. ✅ `utm_source=native_ios` 공유 링크와 브랜드 공유 문구 적용.
- 웹 에버그린 콘텐츠 1~2편으로 SEO 씨뿌리기(계절성 방어). ✅ `/guides/kindergarten-selection` 1차 가이드 추가.
- 모집철 캘린더 기반 **로컬 알림**(백엔드 0, 리텐션 엔진).
- AdMob 위치만 최적화(목록 네이티브 1개), 그 외 광고 자제.
- 의도 데이터 모니터링 → H2 게이트 판단.

### ⛔ Don't (H1)
- 유료화 기능(시즌패스/결제) 빌드 — 시기상조.
- 소셜 티커 — 규모 전엔 신뢰 자해.
- 무료 비교/리포트 유료화 — 바이럴 살해.
- 가짜 마감·가짜 카운트다운 — 신뢰 즉사.
- 전면광고(interstitial) — 신뢰 상품 자살.
